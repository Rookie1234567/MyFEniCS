# docs 文档编写与模型总账规则

本文件作用于 `docs/` 及其全部子目录；与根目录 `AGENTS.md` 一起执行。

## 1. 通俗解释原则

- `summary.md`、`response_vN.md`、`review_report_vN.md` 和面向审阅的技术文档不得默认读者已经理解有限元、电磁仿真、求解器或软件工程术语。
- 新方法、算法、优化策略或指标首次出现时，必须先用通俗语言解释：它解决什么问题、为什么需要它、改变了原计算流程的哪一步、收益是什么、代价和适用边界是什么。
- 不得只写 `static condensation`、`DWR`、`selective trace`、`preallocation`、`warm cache` 等名词后直接给结论。
- 结果表必须说明模型是什么、采用什么方法、为什么比较、每个指标表示什么，以及成功或失败的具体原因。
- 负结果不能只写 `failed`、`controlled negative` 或 `10/12`；必须列出具体不满足的物理量、衍射通道、残差、资源或架构条件。

## 2. 开发模型总账维护

- 仓库级模型总账为 `docs/development_model_registry.md`。
- 每次正式 PDE、重型资源运行、成功迭代解、受控负结果或资源停止后，必须同步更新总账；不得只更新单个 Task 的 response/outcomes。
- 对具备逐级衍射数据的固定 Task034/035/035b 模型，优先报告 12 个显著通道：`R/T (m,n)=(0,0),(-1,0),(-2,0),(-4,0),(-5,0),(-7,0)`，并同时报告 `R_total/T_total/A`。
- 有复振幅时应记录 real/imag 或 magnitude/phase；没有时明确写 `未记录`，不得由功率反推。
- 总账中的 `成功/失败/受控负结果/未完成/未运行` 必须与原始 evidence 一致，不得为表格完整性改变历史分类。
- 新 Task 应在总账第3章新增独立小节，并写明模型、探索目的、实际数值、具体失败项、最终状态和 evidence path。
