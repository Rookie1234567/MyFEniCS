# Response V1：dot 云端并行首批交付

本轮回答用户的首要问题：这些小实验能帮助 0.7 nm 目标模型在约 2 TB 内尽快可用吗？它们给出了一个可进一步验证的局部生成优化、真实模式增长和更可信的共享库存边界，但还没有替代全域 p4 因子，也没有完整目标解。

1. 局部矩阵参考积分复用通过有限组件对照，含准备的本批生成成本约改善 3.67 倍；此比例不能用于预测整场提速。原 G1 的 KSP 已占 76.5%，即全部 setup 消失，整场上限也只有约 1.285 倍。
2. 模式按键嵌套但非前缀；实际 production 已随模式增长提高端口积分规则，M3 的 14×14 局部测试误差约 2.25e-10，不建议根据人为 8×8 负对照修默认。
3. 结构化带缺口大尺寸的纯几何计数只有 211 原始材料+metric 类型，不能假设每个 cell 都存独立因子而宣称必需 17 TB。方向类型、实际共享和同时库存仍未知。旧 2 nm 全域 p4 用量约 916.7 GB 是风险证据，但其矩形无缺口几何不同，不能直接推算本目标。

当前仅本新建独占分支被修改，未修改其他分支或用户电脑。没有开 PR/merge，没有资格化目标 PDE。下一步应围绕准确 p4 全域因子与每步纠错的可扩展替代形成一个有明确对照、局部/全局总预算和失败停止条件的方案；不要重复旧低内存强逆参数扫描，也不要用局部加速掩盖尚未解决的完整求解问题。

后续有界候选：先检查真实 G0 p4 CSR 与实际纠错 RHS 的可用性，再判断混合精度因子加精化是否值得验证；当前云端没有这些实际输入，不能用局部 SVD 或玩具矩阵代替。历史 BLR 压缩已有失败证据，不默认重跑参数扫描。本批仅形成该下一步判断，没有宣称新候选通过。
