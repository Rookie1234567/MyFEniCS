## 2. 必须在正式恢复前一并关闭的两处缺口

### 2.1 选核范围必须和当前观察数据分开

资源门是为了避免与其他任务争用处理器。当前[durable_w1](../../src/runners/w1_component_receiver.py)先在允许核范围内选择，再把自身固定到一个核并启动tmux；内层[audit](../../src/runners/task042_shared.py)随后用继承的单核affinity构造全部候选范围。因此内层说“没有核”，实际可能只是在说“这个核现在不合格”。这不授权忽略它的繁忙状态，应保留全部原排除规则并检查其他允许核。

本审阅只做一次宿主机只读观测，没有tmux、R重新准入、生成或FE：轻监督选CPU12，内层原始忙率0.2695652174，扣除本观察进程实测13 ticks、保留2 ticks后仍为0.1565217391，高于0.05，所以该核正确拒绝。随后**不再采样、不改阈值、不删除任何邻线程**，用保存的同一内层数据和原允许拓扑调用实际spare_cores，得到11个候选：1、8、11、14、15、17、19、20、31、40、42。它证明候选范围缩窄会造成不必要的整链退出；这些旧时间点的候选不是现在的启动许可。

这次观测含轻监督父进程，和旧tmux链不同；不把它当成旧两次失败的精确归因，也不把未归属的CPU差值全部减成“自己”。完整观测3.109534s、整树峰81,743,872 B、swap0、已清场。没有修改任何邻任务。

下一版保留原观察器，新增明确的W1可选候选范围：外层在pin之前保存允许affinity、拓扑及自身身份；内层在**当前新样本**上检查这个经验证的允许范围与当前cpuset限制的交集。观察器可以仍固定单核，只能扣自己已测且匹配的工作量；不能拿“父进程大概在这里”扣负载。其他核的原始忙率、SMT sibling、邻任务窄affinity和活跃宽线程排除全部保持。优先原核；不合格则只从同一次新样本的合格集合选一个，再按PID/start/owner/socket绑定本任务server、pane及后代。不得扩到原允许集合之外，不得固定尝试一串CPU号，更不得改别人的affinity。

audit在抛异常前也必须交付结构化观察：候选范围及来源、CPU原始/调整后分数、计数区间、观察者补偿、topology、邻PID/TID/start与逐核排除理由。保留缺项为UNKNOWN。选择与记录可拆为同一现有实现的两个步骤，不复制第二套准入算法；可选参数默认保持其他调用方原行为，改动只在本分支。

### 2.2 R必须通过真正的封存及消费者，不只测试receipt字典

[recover](../../src/runners/w1_input_recovery.py)把冻结源码的相对Git路径、bytes、sha256放进git_sources。通用[seal_stage](../../src/io/w1_evidence.py)递归把任何具有这三个字段的对象都当成磁盘数值artifact，要求位于output_root父目录。R成功后必然调用该封存；Git路径会被解析到仓库src等目录，触发W1_EVIDENCE_PATH_SCOPE。

本审阅以实际源码记录形状调用**未修改的seal_stage**，直接复现上述异常，生成与FE次数均0。16项测试没有走这个完整的成功出口。此为尚未触发的确定性代码缺陷；V26实际停止仍是CPU门，不能反写成当时发生了封存失败。

应明确区分Git blob身份与磁盘artifact收据：前者核对固定commit/path/bytes/hash，后者核对允许目录、文件字节和重开结果。允许小型类型／字段修正，禁止简单忽略所有越界路径或跳过原数组。完整fixture必须走**候选→成功监督→正式writer→seal→重开→validate_originals→B前置**；另对坏Git源码、坏manifest、改hash但坏内容、未清场监督、缺失sealed artifact给负控。旧ledger白名单仍只有两份原hash。

当前实现先写最终receipt及R_B_inputs，再调用seal_stage；这个先后顺序也需一起改好。最终可供B使用的输入标记必须最后提交，依赖完整且成功的恢复封存；中途异常留下的candidate／partial不能启动B。发生纯封存错误时复用正确候选字节修复后处理，不重新调用生成器。所有异常路径的charge、退出及清场都要落盘，未测峰不能补造为0。
