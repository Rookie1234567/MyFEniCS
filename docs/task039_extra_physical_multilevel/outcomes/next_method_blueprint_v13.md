# 下一方法蓝图 V13：修复诊断内存生命周期与证据保存

唯一优先项是 `IMPLEMENTATION_OR_METRIC_REPAIR`。修复必要性有明确证据；生产 PC 的选择仍未完成。本文件提出可实现的修复合同，不声称这些修复已经实现或经过真实计算验证，不授权本轮再次运行。

当前诊断需要同时保存局部响应、比较不同组合，并计算真实场误差。问题出在保存和释放的顺序：已经拥有 42 列局部响应及其算子像，又另建 48 列完整空间，还保留不用的积分基表。P3 的明确同时存活载荷下界为 273,571,328 B，超过 256 MiB；这使原有仅检查部分数组的内存 Gate 不能成立。修复的是这个诊断流程，原宏块 PC 的数值能力没有因此改善。

## 1. 数学合同不变

仍用同一真实 A4、42 块、输出权重和完整 C_U。C_U 提供已有的全局粗修正，d 是各局部解的加权和，-t 是随后扣除的粗反馈；保存这些方向后可以改变组合系数，而不重新作用 PC。M04 衡量场的积分强度，K04 衡量经 k0 缩放的旋度能量；下式 curl6 指未缩放的 curl-curl 双线性形式对应算子。

```text
a = C_U g
h = g - A4 a
d = sum_i R_i^H W_i D_i^(-1) R_i h
t = C_U(A4 d)
B4(g) = a + d - t
Z_j = 实际右预条件调用 B4(v_j) 的输出
L = [Z, a, p_1, ..., p_42, -t]       # 至多48列
L10 = [a, p_i1, ..., p_i8, -t]       # 至多10列，不包含Z
M04 = P64^H M06 P64
K04 = P64^H (k0^(-2) curl6) P64
```

I4 仍零初值、最多四次 B4；QR/SVD 相对截断仍为 `1e-12`。参考场只评价误差和计算标注为 reference-only 的最佳场组合，不进入 PC、选择器或初值。固定 D 的离线候选在 01 上已违反场误差减半条件；不能将该结果外推为未来改变搜索方向的尺度化 Krylov 必然无效。

## 3. 可检查的容量目标

令 N=48,960、k≤48，每个 complex128 元素16 B。下列是下一次实现的**拟议容量合同**，不是已测通过的预测：

```text
X + AX                              <= 2*N*k*16 = 75,202,560 B
一个阶段的QR或weighted QR工作区       <= 2*N*k*16 = 75,202,560 B
固定对象及流式metric工作池             <= 64 MiB
小矩阵、Python对象和额外分配保留         <= 16 MiB
合计                                <= 234,291,200 B = 223.4375 MiB
诊断硬上限                           = 268,435,456 B = 256 MiB
```

固定工作池必须包含三输入及旧解、native maps、metric action/Vec、P64 临时量、当前 a/h/d/t 和局部观测。选择器与48列求解不并行占用工作区；外部 QR/LAPACK 的副本也必须计入，不能把公式当作库实际分配的证明。64 MiB 或16 MiB 子项未经实际对象清单验证，或者任何阶段超过总额，就停止资格化，不自动提高配额。48列 arena 与工作区都要在输入结束时释放或复用。

2.5 GiB 局部库存、1 GiB 临时预留、V11 allocated 配额公式、单实例上限和整机 reserve/launch/zero-swap 要求独立保持。该修复不声称消除 0.7 nm / 2 TB 的扩展障碍。
