# V12 正式构建前的内存生命周期口径（预运行草稿）

本表说明哪些对象会同时占用内存。局部库存是对保留的局部矩阵、因子和缓存逐项计费的保守账；RSS 是某时刻整个进程树实际占用的物理页，两者不是同一指标。下表还没有 V12 的正式运行实测，不能据此宣布完整 PC 通过资源 Gate。

| 对象 | 口径及当前数值 | 同时存在的阶段 | 来源与边界 |
|---|---|---|---|
| 42 个局部矩阵与 MUMPS 因子 | 新 profile 库存总 cap 2,684,354,560 B；allocated 保守账 + CSR + shared/index/cache | 构建后至外层停止并释放辅助对象 | 配额策略沿 V11；used 单独列出，不用于代替 allocated 放行 |
| 每块 symbolic / numeric / 回代工作 | 每实例 536,870,912 B 门槛；按既定 E/Q 公式 | 当前块构建与回代 | 前后实测与原始 MUMPS 字段将由 V12 records 补充；不重新校准 |
| 局部类矩阵、索引、Floquet 映射与覆盖权重 | 包含于局部库存，共享 ndarray 底层存储只计一次 | 局部装配、B4/I4、外层 | 与 retained factor 同时存在；不能在 builder 完成时漏记后建缓存 |
| W/P owner 缓存与局部内部响应 | 完整 C_U 所需实际当前材料数据，计入相应保留库存 | W 构建后、C_U、外层 | 新 after-W / after-C_U 边界重算；不能用旧覆盖阶段库存替代 |
| 全局 S/p2 矩阵及底层因子 | 不超过 8,192 总行及 536,870,912 B 门槛 | C_U 建成至辅助对象释放 | 单独预算，同时计入全过程内存；不把整个局部库存再加到其单实例预算 |
| p6/p4/p2 空间、相容传递、原 A6 与 native/cached A4 | V12 实测待补 | 构建、内部检查和外层；恢复时仅保留必要对象 | 不重新构建全局参考，不保留 p4 全局 LU |
| Fourier-DtN、H6 正定层级 | V12 实测待补 | 完整 PC 及外层 | 80 模式固定；求解完成后释放不再用于恢复的层级 |
| 四步 I4 的 V/Z 基数组 | derived 53,084 × 16 × 9 = 7,644,096 B | 单次内部 I4 | 仅基数组，不含 rhs/residual/work vector 和 PETSc 容器；每次从零开始，无历史池 |
| restart32 的 V/Z 基数组 | derived 173,802 × 16 × 65 = 180,754,080 B | R32 外层求解 | 仅基数组；每周期丢弃搜索基，保留当前解 |
| restart64 的 V/Z 基数组 | derived 173,802 × 16 × 129 = 358,727,328 B | R64 外层求解 | 比 R32 基数组多 177,973,248 B；两个 probe 顺序运行，不同时保留其基 |
| 局部构建临时预留 | 1,073,741,824 B，独立于局部库存 cap | 符号分析、矩阵转换和局部因子构建等相关阶段 | 进入整机检查，不能挪作增加局部常驻的理由 |
| 检查向量、参考评价数据与恢复包 | V12 实测/派生体积待补 | 各次检查、检查点、输出恢复 | 参考只用于评价，不进入 PC 或初值；保存后释放不需要的向量 |
| 全流程进程树/cgroup | V12 同期峰值待补 | 从启动至所有后代退出，含输出恢复 | RSS/PSS/cgroup、MemAvailable、job/global swap 和磁盘分别记录；不相加不同阶段历史峰值 |

固定的整机规则为 reserve = max(4 GiB, 15% effective_total)，effective_total 取物理与可见 cgroup 限制的较小者；launch cap 不超过 min(12,000,000,000 B, effective_available - reserve)。正式启动时记录实际 envelope，运行时仍执行动态可用内存和进程树检查。表中预算上限和基数组体积不能冒充已证明的整机峰值上界。

旧 V11 的 1,918,558,208 B watchdog 峰值只覆盖当时 41 块构建停止之前的生命周期，不能作为完整 C_U、I4、p6 外层或输出恢复峰值。新 profile 提高库存上限也不能追溯改判旧 V11 结果。
