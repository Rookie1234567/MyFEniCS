## 2. 正确性成立，但不能变成完整前向资格

此方法让预测器估计下一个系数，再保存真实值与预测值的全部二进制异或差异，解码时逐位复原；预测错误增加存储，不能改动系数。它改变历史向量的保存／读取方式，不改变有限元空间、原方程或收敛过程。

数据仍是旧64hex／p6／q15有限体积问题：45000 native槽、42624独立系数，其中13824 trace（相邻单元共享的边／面系数）与28800单元内部系数；旧A没有完整DtN，即没有接齐开放边界的辐射条件。V47的train16／val4只读canonical及实体映射，没有读制造波方向／偏振／包络参数训练。heldout8首次消费在FREEZE之后的失败迁移入口，已成为本轮已消费集合，不能再封存重用。V45公开prefix／residual各8条只作冻结后的迁移诊断，不是新盲测，不读取其sealed标签或调参。

## 4. 本审阅勘误和复用限制

### 4.1 真实consumer瞬时保留两条解码向量

[`consume`](../../src/solvers/lossless_vector_bank.py)在循环内执行`vector = bank.get(i)`。Python先完成右侧：`get`／`_decode`创建新的完整out时，局部变量`vector`仍引用上一条；新返回完成后旧引用才释放。因此实际消费不是严格的“一条完整解码workspace”。同样的getter引用问题也可能在checker循环出现。

审阅以实际`consume`和3×12复数的合成getter、weakref做了最小寿命见证，六次读取存活数量为`1,2,2,2,2,2`，最大2；没有读取科学数组、调用NN或FE。脚本和输出附在独立核验记录。对本数据，额外一条完整trace为221184B；若相同实现直接迁到目标则每条1684779264B。这里是引用寿命推断和小合成验证，不是新的目标分配或RSS实测。

所以不授Review V45要求的严格单解码向量生命周期资格。既有宽裕block规划是否覆盖这段瞬时重叠，不能靠名称或相加猜测；不能将已发布“complete规划”提升为经过逐对象寿命证明的最小／硬上界。整树采样值仍是真实记录，逐位正确性不受影响，NN失败也不受影响，因为其resident下界已足够拒绝。

**若未来在实质新合同中复用VectorBank，必须先修此生命周期问题**：明确使用预分配输出或在下一get前释放旧引用，给出实际decoder分配／引用见证并重验有限consumer，不必重新训练。同步约束解码工作区、backend缓冲及ABI指纹；当前绑定的NumPy／libc／平台字段不能当任意BLAS构建和跨平台推理位一致证明。本报告不为这个局部修复单开V49或要求数值重放。
