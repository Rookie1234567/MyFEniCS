# CPU准入误排修复：只回放冻结快照，不重开V79

桌面线程偶尔会在多个CPU上运行几毫秒。旧规则把“采样期间用过CPU”直接当成“其最后运行的整个核被占用”，使低负载核也被排除。本次用户明确授权仅修复这一分类并作离线回归，不授权科学计算或重开已关闭窗口。

修正规则保持每CPU忙碌率大于5%即排除；宽亲和线程改为按真实时间占用判断：`delta_ticks / (sample_interval_seconds * SC_CLK_TCK) > 0.05`，仍排除其最后运行的CPU及全部SMT兄弟。规则不按桌面或worker的名称放行，较高占用的桌面线程同样被排除。窄亲和线程（最多16个CPU）仍完整保留其亲和集合，包括休眠的loader；线程活动缺失、异常或身份不能配对时仍保守排除。

两份快照采样约1.16/1.15秒，Linux时钟频率100 ticks/s；当前只读确认与快照处于相同boot。线程的5%界线分别为5.820920和5.734983 ticks，未取整、未放宽阈值。因此有6 ticks活动的后台线程仍可能被排除。短采样不能证明未来持续空闲，也不能替代机器锁、内存、压力等其他准入。

两份原始拒绝记录、stderr、费用、V79 window/ledger以及旧response/outcome均不修改。旧无策略标识的收据继续按旧规则重放，仍得到0候选；新收据明确保存`sampled_fraction_v1`、采样秒数及clock ticks。checker按已绑定策略独立重算，不把新规则追溯写成旧准入通过。判定和排除表共用同一实现，避免结果与说明不一致。

26项定点回归通过，包含两份真实冻结JSON、旧策略兼容、5%边界、时间归一化、持续worker、窄亲和、SMT兄弟、未知活动拒绝和无名称白名单；相关compile及Ruff通过。只读ABI导入首次受沙箱本地MPI套接字限制，放行本地singleton导入后原complex128/int64栈核对通过；未启动mpiexec科学作业、网格、PDE、作用、KSP或factor。没有全库pytest或历史科学数组扫描。
